# Bot Distribuidor de Tenis
mai
Aplicación local para conservar publicaciones y fotos de calzado, revisar el precio del proveedor, calcular un margen en COP y preparar el flujo de distribución.

**Estado actual: prototipo local con conexión experimental de Baileys.** Admite varias cuentas y perfiles de proveedor. Cada foto que llega a un grupo proveedor se conserva como referencia separada junto con su descripción; los importes claros se ajustan por el margen de ese proveedor y los dudosos se dejan para revisión. En el detalle puedes corregir el código, elegir la esquina y comparar la foto original con la copia marcada. Puedes enviar una referencia o pulsar **Aprobar todo y enviar todo** para la cuenta y el filtro seleccionados. Un envío incierto se detiene y no se reintenta automáticamente. El plan completo está en [`PLAN.md`](./PLAN.md).

Baileys es una implementación comunitaria no oficial del protocolo de WhatsApp Web, no una API aprobada por Meta. [Los términos de WhatsApp](https://www.whatsapp.com/legal/terms-of-service) y su [guía de uso responsable](https://faq.whatsapp.com/361005896189245/?eea=0&locale=en_US) restringen usos no permitidos y pueden ocasionar restricciones de cuenta; el [proyecto Baileys](https://github.com/WhiskeySockets/Baileys) también advierte que es una biblioteca no oficial y que desaconseja mensajería automatizada o masiva. No hay técnicas para ocultar automatización, evadir controles o rotar cuentas. Usa solo grupos propios/autorizados y publicaciones con permiso del proveedor.

## Requisitos

- Node.js 24 LTS x64.
- pnpm 11.25 o una versión compatible con `packageManager`.
- Windows 11 o macOS para desarrollo local.

## Instalación

En macOS:

```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install
cp .env.example .env
pnpm dev
```

En Windows PowerShell:

```powershell
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install
Copy-Item .env.example .env
pnpm dev
```

Abre `http://127.0.0.1:5173`. El servicio guarda su base y las imágenes en una carpeta local de datos de la aplicación, fuera del repositorio. La configuración predeterminada es simulación y enlaza el servidor en loopback.

Para validar la compilación de producción:

```powershell
pnpm build
pnpm start
```

El servidor usa `127.0.0.1:3210`; si se cambia `PORT`, configura también el proxy de Vite para desarrollo. `DATA_DIR` debe ser una ruta absoluta. No pongas la base de datos dentro de una carpeta de red o sincronización activa.

## Uso

1. Para habilitar la conexión, cambia `APP_MODE=experimental` y `WHATSAPP_ENABLED=true` en `.env`; reinicia el servidor. Mantén `WHATSAPP_SEND_ENABLED=false` hasta validar la recepción.
2. En **Cuentas de WhatsApp**, conecta cada número por QR, actualiza sus grupos y guarda hasta cinco destinos. Cada cuenta conserva su propia sesión, proveedores y destinos; ahí puedes ajustar el intervalo entre fotos y el rango diario para recuperar historial (16:00–19:00, hora de Colombia, inicialmente). Configura las horas en **Desde** y **Hasta**. Si WhatsApp está conectado, **Guardar y recuperar** guarda el rango e inicia un intento; si todavía no comenzó, lo programa para la hora inicial; **Recuperar historial** permite reintentar el rango guardado sin desconectar. Mantén WhatsApp del teléfono conectado a Internet. La recepción de mensajes nuevos permanece activa a cualquier hora mientras la aplicación y WhatsApp estén conectados.
3. En **Reglas por proveedor**, crea un perfil por grupo de origen. Configura por separado la ganancia de **PRECIO** y **CAJA** (incluido $0), la marca de bodega y la esquina predeterminada. Por ejemplo, con $10.000 para PRECIO y $5.000 para CAJA, `PRECIO $45.000` y `CAJA $35.000` se publican como `$55.000` y `$40.000`. Si una bodega ya publica con tu ganancia incluida, configura ambos márgenes en $0. Toda línea que contenga **DOCENA** o **DOCENAS**, incluida **CAJA Y DOCENA**, se excluye del cálculo y se elimina de la descripción publicada, con o sin importe y sin distinguir mayúsculas; la publicación recibida permanece intacta en el catálogo. La aplicación no adivina ni recalcula reglas para referencias existentes.
4. Las fotos y descripciones nuevas de los grupos proveedor seleccionados aparecen en **Catálogo** a cualquier hora mientras la aplicación y WhatsApp estén conectados. Al reconectar, el historial se filtra por el día en curso en Colombia y por la hora original de envío: con 16:00–18:00 solo se recupera lo enviado desde las 16:00 hasta antes de las 18:00, aunque abras la aplicación a las 19:00. Con 16:00–19:00 se incluyen también las publicaciones de las 18:00 a las 18:59. Los mensajes anteriores al rango y los de otros días se omiten. Los rangos que cruzan medianoche corresponden al último inicio de rango. La bandeja local solo mantiene mensajes pendientes de procesar, sin esperar a que abra un horario; los mensajes nuevos guardados allí sobreviven a reinicios. El catálogo, fotos e historial de envíos se conservan al reiniciar. Cada fotografía se analiza automáticamente en segundo plano antes de permitir su envío; el panel muestra si se conservará original, se añadirá una marca o requiere revisión. Revisa precio, código y vista previa. En cada foto puedes elegir siempre **Conservar original**, **Agregar solo código**, **Agregar solo mundo**, **Agregar ambos** o **Usar detección automática**. Las decisiones manuales tienen prioridad sobre el OCR y se conservan al repetir el análisis o cambiar el código y la esquina. Las opciones que agregan código requieren que lo indiques. La descripción que se enviará se puede editar antes de distribuir el producto; usa **Guardar descripción** si ya está aprobado. Se mantienen los importes aprobados y se limpia de nuevo cualquier línea con docena. Los códigos explícitos `COD`/`REF`/`SKU` se reconocen junto con formatos como `015-81` y `096-215` inmediatamente después de `MUJER` o `HOMBRE`; se conserva el cero inicial. También se reconoce una referencia al principio del nombre, como `1059 *ADIDAS REPÓNSE DAMA $75.000*`; no se interpreta como referencia un importe, talla o cantidad. Si no se detecta un código, **Agregar solo código** y **Agregar ambos** abren un cuadro para escribirlo y guardarlo con la decisión de marcado. Si hay conflicto, corrígelo en la revisión. Cada fotografía es un producto; una descripción posterior solo se asocia cuando hay una única foto reciente compatible, en los demás casos queda para revisión.
5. Para autorizar envíos reales, cambia también `WHATSAPP_SEND_ENABLED=true` y reinicia. Usa **Aprobar TODO** para confirmar todos los productos de la cuenta y el proveedor seleccionados, incluidos los precios y las fotos en revisión. El cuadro muestra las descripciones e importes, permite completar precios faltantes y elegir el marcado manual de las fotos dudosas; las fotos listas conservan su decisión. Si faltan fotos, márgenes o datos válidos, se rechaza el lote completo y se indica qué corregir. Esta aprobación no envía mensajes. Después, envía una referencia o usa **Enviar aprobados** o **Enviar seleccionadas**. La confirmación muestra cuenta, cantidad y destinos; los precios o fotografías ambiguos no se envían. El resultado masivo identifica las referencias omitidas. Cada cuenta aplica una pausa configurable entre fotos (10 segundos por defecto, mínimo 5), compartida entre sus grupos y conservada al reiniciar.
6. En **Historial**, consulta por cuenta la recepción de fotos y descripciones, preparación de precios, conexión, cambios de reglas y resultado de cada foto enviada. Puedes filtrar por tipo, estado y búsqueda; el historial se actualiza mientras la pestaña está abierta. La confirmación de Baileys no garantiza entrega a los miembros del grupo.

La opción de conexión se habilita en macOS y Windows: la clave maestra queda en el Llavero de macOS o protegida con DPAPI CurrentUser en Windows, y credenciales/claves Signal se guardan cifradas con AES-256-GCM dentro de SQLite. El primer acceso puede solicitar permiso del almacén seguro. El QR es temporal y se entrega solo al panel local. La clave del almacén está ligada al usuario del sistema; mover solo SQLite a otra cuenta/equipo no traslada la sesión.

## Alcance del conector

Al vincular o reconectar una cuenta, el adaptador acepta los lotes de historial inicial, completo, reciente y las respuestas a solicitudes puntuales que Baileys entregue, con un límite máximo de 24 horas y procesamiento de mensajes únicamente si pertenecen a grupos proveedor activos de esa cuenta. El historial se limita además al rango configurado para el día de trabajo, según la hora original de cada mensaje. Al conectar y al guardar un rango con la cuenta conectada, la aplicación solicita historial por cada grupo proveedor activo mediante `fetchMessageHistory`, con referencias reales de mensajes y timestamps en milisegundos. Recorre lotes de hasta 50 mensajes, el máximo indicado por Baileys, hasta superar la hora inicial, con una pausa entre solicitudes y un máximo de 20 lotes por grupo para evitar solicitudes sin fin. Si el rango aún no ha comenzado, el intento queda programado para la hora inicial mientras la conexión permanezca activa; no termina prematuramente por falta de mensajes de un rango futuro. El panel muestra los grupos solicitados, los que no tienen una referencia y las solicitudes fallidas. Guardar o pulsar recuperar muestra si el intento quedó programado, espera referencias o puede solicitar grupos; el Historial de actividad marca los casos sin solicitud como advertencia. Si falta una referencia, la solicitud se inicia cuando llega un mensaje nuevo de ese grupo. Las referencias se conservan entre reinicios; también se recogen las claves reales incluidas en la sincronización inicial y las actualizaciones de chats, aunque aún no se hayan configurado proveedores. Solo se retienen el último identificador de mensaje, su hora y autor por grupo de esa cuenta, sin cuerpos ni fotos descartadas. Las solicitudes y la incorporación al catálogo siguen limitadas a proveedores activos. Una fecha de conversación sin clave real de mensaje no sirve como referencia y no se inventa ninguna. Si faltan referencias utilizables, el aviso distingue que no se pudo solicitar historial de que se hizo una solicitud sin respuesta. Por ejemplo, con 07:00–22:00 al abrir a las 10:52 se puede recuperar de 07:00 hasta ese momento; no hace falta esperar hasta las 22:00. La aceptación de una solicitud no se muestra como recuperación exitosa: el contador solo aumenta cuando llegan mensajes nuevos del rango. Por ejemplo, al abrir a las 20:22 con 17:00–20:00 se pide ese rango aunque ya haya terminado. Baileys/WhatsApp no garantiza que entregue todo el historial ni permite asegurar que la recuperación esté completa; el panel muestra cuántos mensajes fueron entregados y una advertencia. En una vinculación nueva por QR se solicita la sincronización de historial completo con el perfil macOS Desktop; en cuentas grandes puede aumentar el tiempo de conexión y el uso de memoria. Una cuenta ya vinculada no puede forzar esa sincronización completa con el botón Recuperar historial. Si un evento de chat incluye el último mensaje con contenido, también se procesa esa publicación: la solicitud puntual comienza antes de la referencia y no devuelve necesariamente ese mismo mensaje. El rango solo filtra la recuperación del historial: los mensajes nuevos se reciben y procesan a cualquier hora. Una notificación (`notify`) o un mensaje anexado (`append`) anterior al inicio de la conexión también se considera recuperación y debe cumplir el rango. Las publicaciones ya recibidas se conservan al cambiarlo. Si llegan después de terminar el intento inicial de recuperación, el panel actualiza el estado y el contador; también cuenta los mensajes recuperados dentro del rango entregados como anexados (`append`) o notificaciones antiguas (`notify`), sin volver a contar los ya guardados. Las consultas de grupos se comparten entre eventos y usan una pausa si WhatsApp responde `rate-overlimit`. El programa reconecta al iniciar solo cuentas con credenciales guardadas y no genera QR para cuentas nuevas automáticamente. Cada foto abre una referencia independiente. Una descripción en el mismo mensaje se asocia a esa foto; una descripción en un mensaje cercano solo se adjunta si existe una única fotografía compatible del mismo remitente en esa cuenta y grupo. Si hay varias fotos posibles, la asociación queda pendiente para revisión. El envío publica una foto marcada por grupo con el texto ajustado como descripción.

Después de escanear un QR, WhatsApp puede cerrar el primer socket con `restartRequired` (515) para que el cliente vuelva a abrirlo con las credenciales recién emitidas. El adaptador guarda esos cambios antes de reiniciar el socket; otros cierres quedan visibles en el panel para diagnóstico y reconexión manual.

La descripción enviada quita los emojis decorativos y conserva el texto, los saltos y el formato; `💲` se convierte en `$` para mantener clara la moneda. La descripción recibida permanece intacta para consulta.

El OCR de [Tesseract.js](https://github.com/naptha/tesseract.js/) y la búsqueda visual empiezan automáticamente al guardar la fotografía y se ejecutan en este computador. Se revisan las cuatro esquinas para asociar código y mundo en una misma etiqueta; por ejemplo, `960 A 🌍` se conserva sin cambios cuando el código del producto es `960`. Si hay una etiqueta parcial clara, se añade únicamente lo que falta. Si la lectura falla, es incierta o muestra un código diferente, el envío queda bloqueado hasta que confirmes la foto original, corrijas el código o indiques qué marcar. **Volver a analizar las fotos** repite la lectura local. La letra de la etiqueta se toma de palabras completas de la descripción: **D** para DAMA, MUJER o D; **H** para HOMBRE, VARÓN/VARON, CABALLERO o H. Se aceptan minúsculas y plurales. Las letras aisladas no se buscan dentro de marcas ni códigos; si aparecen ambos géneros no se adivina uno. La letra se coloca inmediatamente después del código y antes del mundo, por ejemplo `1059D 🌎` o `1059H 🌎`, sin repetir el mismo sufijo cuando ya forma parte de un código numérico. El original permanece intacto. En macOS la etiqueta usa San Francisco y Apple Color Emoji del sistema; en Windows usa Segoe UI y Segoe UI Emoji, y otros sistemas usan los recursos Noto/Twemoji incluidos. Las fuentes del sistema no se copian ni distribuyen. La etiqueta queda desplazada hacia el interior de la foto en cualquiera de las cuatro esquinas. La primera inspección necesita conexión para descargar y guardar los archivos de idioma del OCR en `ocr-cache/` dentro de la carpeta local de datos; las imágenes no se envían al servicio de descarga. Los importes incrustados no se alteran mediante OCR. Solo se aprueba automáticamente un precio textual con etiqueta inequívoca y sin conflicto. El estado `submitted` indica que Baileys devolvió el identificador de mensaje; no prueba entrega o lectura por los miembros.

Si aparece `Bad MAC` o `Failed to decrypt message with any known session`, WhatsApp no pudo validar/descifrar uno de los mensajes con sus sesiones disponibles. Baileys conserva sus reintentos de recepción; el programa no desactiva la comprobación criptográfica ni reinicia la vinculación automáticamente. Para grupos proveedor activos, la publicación afectada queda como error de descifrado en la bandeja y en Actividad, sin incorporarse ni contarse como historial recuperado. Si después llega descifrada con el mismo identificador, se procesa sin duplicarla y se limpia el error de la bandeja. La rotación de sesiones Signal no implica por sí sola una desconexión de la cuenta. El parche reproducible de `libsignal@6.0.0` elimina los objetos de sesión de sus mensajes de consola para no imprimir claves privadas; conserva los errores criptográficos y no cambia el cifrado. Se aplica con `pnpm install` a partir del archivo de bloqueo.

## Motor local de análisis de imágenes

El motor `local-ocr-consensus-v2` mantiene el OCR español/inglés y la comparación visual en el computador. El análisis completo se ejecuta en workers de Node, fuera del proceso que atiende WhatsApp y el panel. Por defecto usa un worker, o dos si hay al menos cuatro CPU disponibles y 2 GiB de memoria libre al iniciar. `IMAGE_ANALYSIS_WORKERS=1` a `4` permite ajustar el límite; cada worker reutiliza su OCR. Un análisis que falle o supere 120 segundos queda para revisión y el worker se reemplaza si se cerró o quedó bloqueado. Al cerrar, las fotos que aún estaban esperando permanecen pendientes y se retoman al iniciar.

Se comparan las lecturas de cada esquina y se envían a revisión los códigos contradictorios o con confianza insuficiente. Cuando hay un mundo localizado, se prepara un recorte de texto separado del emoji: así se evita leer el mundo como un dígito adicional. Los recortes se amplían para leer etiquetas pequeñas. La puntuación del OCR es una señal interna, no una probabilidad calibrada de acierto.

El resultado visual se reutiliza para fotos con exactamente el mismo SHA-256 y versión de motor, incluso entre reinicios. Las decisiones manuales permanecen separadas por fotografía. **Volver a analizar las fotos** fuerza una lectura nueva; los errores no se guardan en caché. El resultado cacheado se elimina al borrar la última foto que lo utiliza. Una nueva versión del motor vuelve a analizar los resultados automáticos anteriores al arrancar y conserva las decisiones manuales.

Los detalles del análisis de cada foto muestran su tiempo y si se reutilizó un resultado. La actividad guarda también la versión y las lecturas OCR realizadas. `GET /api/image-engine?sessionId=main` devuelve la versión, concurrencia y estados del análisis de esa cuenta.

Para repetir la prueba funcional con diez imágenes **sintéticas**, sin utilizar fotos de clientes:

```sh
pnpm --filter @tenis/server benchmark:images --output /tmp/image-engine-report.json
```

En Windows utiliza una ruta de salida válida para ese equipo. `--cache-dir RUTA` permite reutilizar los idiomas OCR ya descargados; la primera ejecución necesita internet para descargarlos. La prueba cubre código/mundo en cuatro esquinas, compresión JPEG, código solo, mundo solo, foto idéntica repetida y un código que no corresponde al producto. Informa tiempos, decisión esperada/obtenida y uso de caché; termina con error si una decisión no coincide. Estos casos comprueban regresiones concretas y no miden la precisión del catálogo real. El arranque en frío y las fotos nuevas tienen costes diferentes de reutilizar un resultado: esta mejora no promete que toda foto nueva se analice más rápido.

## Datos y seguridad

- Windows: `%LOCALAPPDATA%\BotDistribuidorTenis\simulation\business.sqlite`; macOS: `~/Library/Application Support/BotDistribuidorTenis/simulation/business.sqlite`. Incluye cuentas, proveedores, productos, grupos, publicaciones, auditoría, actividad local y registros cifrados de autenticación.

Actualizar la lista de grupos conserva los destinos guardados y los grupos proveedor aunque WhatsApp no los incluya en una respuesta parcial. En el detalle de cada producto se muestran también los destinos seleccionados que aún no tienen publicación. Si un producto fue enviado a dos grupos y falta un tercero, **Completar envío a 1 grupo** envía únicamente al pendiente; los envíos individuales y por lote omiten los destinos ya aceptados. Agregar un destino por sí solo no inicia envíos. Los envíos inciertos siguen bloqueados hasta su conciliación.

El catálogo y el historial de publicaciones quedan guardados en SQLite entre reinicios. Marca la casilla de una foto o de una referencia para seleccionar sus fotos; **Seleccionar fotos visibles** respeta la búsqueda y los filtros actuales. **Eliminar foto seleccionada** o **Eliminar fotos seleccionadas** borra únicamente la selección, sin confirmación y en cualquier estado. En el detalle también puedes usar **Eliminar esta foto**. El botón independiente **Eliminar todos** detiene los envíos y vacía todo el catálogo de la cuenta activa, sin aplicar filtros ni selección y sin confirmación, independientemente del estado. Las fotos restantes de una referencia se conservan; al borrar su última foto, también se elimina la referencia. Se interrumpen los envíos de las referencias afectadas y los de las demás pueden continuar. Una foto que ya se haya entregado al conector de WhatsApp puede completarse; los mensajes publicados no se retiran. Las fotos restantes cuyo envío estaba en curso quedan para conciliación. Se conservan las otras cuentas, los proveedores y la configuración, y el evento queda en Actividad. La recepción de nuevas publicaciones sigue activa. Los mensajes recibidos se deduplican por cuenta, grupo e ID de WhatsApp aunque la foto se elimine. El envío por selección incluye solo referencias listas con todas sus fotos seleccionadas.
- La carpeta `media/` junto a la base guarda las fotografías originales por SHA-256. Las copias marcadas se guardan en `media/derived/` y se generan de nuevo desde el original; nunca se superponen marcas sobre marcas.
- El material de autenticación se cifra con AES-256-GCM y una clave maestra guardada en el Llavero de macOS o protegida por DPAPI para el usuario actual de Windows. No subas la base local, `.env`, credenciales, medios de clientes ni capturas de QR; `.gitignore` excluye archivos de runtime.
- El servicio rechaza otros `Host` y orígenes que no sean el panel local.

Las fotos y los datos comerciales del prototipo no están cifrados; protege tu usuario y activa el cifrado de disco del equipo. La protección de autenticación usa el almacén seguro del sistema operativo; la primera conexión de WhatsApp aún requiere una prueba manual en el equipo donde la usarás.

El marcado usa [Sharp](https://sharp.pixelplumbing.com/api-constructor/) y gráficos [Twemoji](https://github.com/jdecked/twemoji) como recursos incluidos o de respaldo; consulta sus licencias y atribución en [`apps/server/assets/THIRD-PARTY-NOTICES.md`](./apps/server/assets/THIRD-PARTY-NOTICES.md). No se descargan fuentes ni emojis al procesar cada foto.
